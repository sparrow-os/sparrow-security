支持国际化的字典表，核心是：**主表管结构和业务编码，i18n 表管展示文本，用不可变 `id` 关联，业务层只传 `type_code + item_code`，缓存按 `type_code + locale` 组织。**

下面给一套完整设计。

---

## 一、设计原则

1. **类型表 + 字典项表**，职责分离。
2. **字典项支持树形**，用 `parent_id` 自关联。
3. **主表保留默认语言**，用于回退。
4. **i18n 表只翻译展示字段**，如 `type_name`、`item_name`、描述、扩展展示属性。
5. **i18n 表用不可变 `id` 关联**，不要用 `type_code`、`item_code`，否则编码改了翻译会断。
6. **业务表只存 `type_code + item_code`**，不存名称。
7. **`type_code`、`item_code` 创建后不可变**，只允许改名称、排序、启停。
8. **强缓存**，按 `type_code + locale` 缓存。

---

## 二、表结构 DDL

### 1. 字典类型表 `sys_dict_type`

```sql
CREATE TABLE sys_dict_type (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  type_code      VARCHAR(64)  NOT NULL COMMENT '业务编码，如 order_status，创建后不可变',
  type_name      VARCHAR(128) NOT NULL COMMENT '默认语言名称，如 订单状态',
  default_locale VARCHAR(16)  NOT NULL DEFAULT 'zh-CN' COMMENT '默认语言',
  status         TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
  is_system      TINYINT      NOT NULL DEFAULT 0 COMMENT '是否系统内置',
  remark         VARCHAR(255) DEFAULT NULL,
  created_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_type_code (type_code)
) COMMENT='字典类型';
```

### 2. 字典类型多语言表 `sys_dict_type_i18n`

```sql
CREATE TABLE sys_dict_type_i18n (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  type_id    BIGINT       NOT NULL COMMENT '关联 sys_dict_type.id，不可变',
  locale     VARCHAR(16)  NOT NULL COMMENT 'BCP 47，如 en-US',
  type_name  VARCHAR(128) NOT NULL,
  remark     VARCHAR(255) DEFAULT NULL,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_type_locale (type_id, locale),
  KEY idx_locale (locale)
) COMMENT='字典类型多语言';
```

### 3. 字典项表 `sys_dict_item`

```sql
CREATE TABLE sys_dict_item (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  type_id     BIGINT       NOT NULL COMMENT '关联 sys_dict_type.id',
  type_code   VARCHAR(64)  NOT NULL COMMENT '冗余，业务查询用，创建后不可变',
  parent_id   BIGINT       NOT NULL DEFAULT 0 COMMENT '父项ID，0表示根项',
  item_code   VARCHAR(64)  NOT NULL COMMENT '项编码，业务存这个，创建后不可变',
  item_name   VARCHAR(128) NOT NULL COMMENT '默认语言名称',
  item_value  VARCHAR(255) DEFAULT NULL COMMENT '附加值，可选',
  level       TINYINT      NOT NULL DEFAULT 1 COMMENT '层级',
  sort_order  INT          NOT NULL DEFAULT 0,
  status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
  ext_json    JSON         DEFAULT NULL COMMENT '默认语言扩展属性',
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_type_item (type_code, item_code),
  KEY idx_type_parent_sort (type_code, parent_id, status, sort_order),
  KEY idx_type_id (type_id)
) COMMENT='字典项';
```

### 4. 字典项多语言表 `sys_dict_item_i18n`

```sql
CREATE TABLE sys_dict_item_i18n (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_id    BIGINT       NOT NULL COMMENT '关联 sys_dict_item.id，不可变',
  locale     VARCHAR(16)  NOT NULL COMMENT 'BCP 47，如 en-US',
  item_name  VARCHAR(128) NOT NULL,
  ext_json   JSON         DEFAULT NULL COMMENT '该语言下的扩展属性，如描述、颜色、图标等',
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_item_locale (item_id, locale),
  KEY idx_locale (locale)
) COMMENT='字典项多语言';
```

## 四、查询与回退

### 1. 按 `type_code + locale` 查询字典项

```sql
SELECT
  i.id,
  i.item_code,
  COALESCE(i18n.item_name, i.item_name) AS item_name,
  COALESCE(i18n.ext_json, i.ext_json)   AS ext_json,
  i.item_value,
  i.parent_id,
  i.level,
  i.sort_order
FROM sys_dict_item i
LEFT JOIN sys_dict_item_i18n i18n
  ON i18n.item_id = i.id
 AND i18n.locale = ?
WHERE i.type_code = ?
  AND i.status = 1
ORDER BY i.level, i.sort_order;
```

### 2. 回退策略

```text
请求 locale = zh-CN：
  zh-CN -> zh -> 默认语言（主表）

请求 locale = en-US：
  en-US -> en -> 默认语言（主表）
```

主表 `item_name` 就是默认语言的兜底值。

### 3. 翻译单个编码

业务传 `type_code = order_status`，`item_code = PAID`：

```sql
SELECT
  i.item_code,
  COALESCE(i18n.item_name, i.item_name) AS item_name
FROM sys_dict_item i
LEFT JOIN sys_dict_item_i18n i18n
  ON i18n.item_id = i.id
 AND i18n.locale = ?
WHERE i.type_code = ?
  AND i.item_code = ?
  AND i.status = 1;
```

## 五、缓存设计

字典读多写少，必须缓存。

### 缓存 key

```text
dict:{type_code}:{locale}
```

例如：

```text
dict:order_status:zh-CN
dict:order_status:en-US
```

### 缓存 value

```json
{
  "CREATED": { "name": "已创建", "value": null, "sort": 10, "ext": {} },
  "PAID":    { "name": "已支付", "value": null, "sort": 20, "ext": {} }
}
```

### 刷新策略

- 修改字典类型或字典项后，删除对应 `type_code` 的所有 locale 缓存。
- 修改某条 i18n 后，刷新对应 `type_code + locale`。
- 可发 MQ 事件，让多实例同时刷新本地缓存。
- 本地缓存：Caffeine；分布式缓存：Redis。

## 六、业务表怎么存

推荐：

```sql
order_status_code VARCHAR(64)  -- 存 item_code，如 PAID
```

如果 `item_code` 不能保证全局唯一，建议同时存：

```sql
dict_type_code VARCHAR(64)   -- 如 order_status
dict_item_code VARCHAR(64)   -- 如 PAID
```

**不要存 `item_name`**，因为名称会随语言和运营修改变化。
**不要存 `type_id` / `item_id` 作为业务外键**，因为业务传的是编码。
如果担心 `type_code` 以后会改，可以在业务表额外存 `type_id + item_id`，但接口层仍传编码。

## 七、接口设计

按类型批量获取：

```http
GET /api/dict/items?typeCodes=order_status,region&locale=zh-CN
```

返回：

```json
{
  "order_status": [
    { "code": "CREATED", "name": "已创建", "value": null, "sort": 10, "ext": {} },
    { "code": "PAID", "name": "已支付", "value": null, "sort": 20, "ext": {} }
  ],
  "region": [
    { "code": "110000", "name": "北京市", "parentId": 0, "level": 1 },
    { "code": "110100", "name": "北京市辖区", "parentId": "110000", "level": 2 }
  ]
}
```

树形结构可以在服务端组装，也可以返回平铺由前端组装。

## 八、管理后台注意事项

1. **`type_code`、`item_code` 创建后禁止修改**。
   只允许改名称、排序、启停、扩展属性。

2. **默认语言必须填写**。
   主表 `type_name`、`item_name` 作为回退。

3. **多语言按需维护**。
   没填的语言自动回退默认语言。

4. **修改后刷新缓存**。
   否则前端看到的还是旧翻译。

5. **树形字典的父子关系在主表维护**，翻译只影响名称，不影响结构。

6. **不是所有字段都翻译**。
   `type_code`、`item_code`、`sort_order`、`status` 永远不翻译。

---

## 九、如果 `type_code` 必须允许修改

那就要接受：业务表如果存了 `type_code`，必须级联更新所有业务表，风险极高。
更稳的做法是：

- 业务表存不可变 `type_id + item_id`。
- 接口层传 `type_code + item_code`，通过缓存映射成 ID。
- `type_code` 修改只影响字典表，不影响业务数据。

但既然业务大概率传编码，最简单还是：**`type_code` 创建后不可变。**

---

## 十、最终结论

支持国际化的字典表推荐：

```text
sys_dict_type           -- 字典类型，主表默认语言
sys_dict_type_i18n      -- 字典类型多语言
sys_dict_item           -- 字典项，主表默认语言，parent_id 支持树形
sys_dict_item_i18n      -- 字典项多语言
```

关键点：

- 主表管结构、编码、默认语言。
- i18n 表用不可变 `id` 关联，只翻译展示字段。
- 业务传 `type_code + item_code`。
- 查询按 `locale`，取不到回退默认语言。
- 缓存按 `type_code + locale`。
- `type_code`、`item_code` 创建后不可变。
- 业务表只存编码，不存名称。

**一句话：主表默认语言，i18n 表扩展语言；用 ID 关联，按编码查询，按 locale 缓存回退。**
